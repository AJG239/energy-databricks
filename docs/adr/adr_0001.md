# ADR 0001: Arquitectura medallion 

- Estado: Aceptado
- Fecha: 22/10/2026

## Contexto

El proyecto recoge los datos de distintas APIs relacionadas con la meteorología y la red eléctrica, sabemos que los datos vienen en formato JSON con una estructura anidada.
Los datos vienen por fechas y horas, junto con valores que pueden ser nulos.

El objetivo del pipeline es ejecutar cada cierto tiempo un job diario para actualizar las distintas tablas con los nuevos valores que provengan de las APIs, para poder 
mantener los datos y dashboards actualizados.

## Posibilidades
1. Realizar el proyecto sin capas: Si se realiza el proyecto directamente sin capas habrá menos tablas pero si una transformación tiene un error hay que volver a ejecutar el pipeline. Es decir, se deben descargar de nuevo los valores de la API y puede llevar a nuevos errores o que exista un límite de peticiones.
2. Utilizar la estructura medallion: Permite tener un mejor control de las transformaciones y posibles errores, pero tienes una mayor cantidad de tablas.

## Decisión

Se escoge la estructura medallion porque permite tener una mejor gobernanza del dato y una mejor calidad a la hora de buscar información dentro de las tablas. De este modo, cada capa cumple un objetivo distinto y solo lee a la anterior: 
 - raw: mete en el landing (es un volumen) los datos como vienen del JSON.
 - bronze: junto con los datos de raw se añaden datos como la fecha de descarga o el nombre del archivo.
 - silver: tabla en la que se realizan transformaciones para limpiar los datos
 - gold: tablas finales que se usarán para el dashboard y el modelo.

## Ventajas

- Los problemas de calidad se detectan y aíslan en un único punto (silver).
- Gold es estable: el dashboard y el modelo no se rompen por cambios de limpieza, y se puede dar acceso solo a gold.
- El linaje de Unity Catalog muestra el recorrido completo del dato.
- Si cambia una regla de limpieza, se procesa silver desde bronze sin volver a llamar a las APIs.

## Desventajas

- Un mismo dato puede estar almacenado varias veces.
- Se necesitan más tareas para realizar todo el procesado.
